# pi-auto-fold：自动折叠执行过程

完成回答后，把工具输出、过程消息、成功恢复后的错误记录收成一行；保留用户消息和最后的成功回答。执行期间的新内容正常显示。

## 安装

推荐通过 Pi 包管理器安装：

```bash
pi install git:github.com/lizhuoran1019/pi-auto-fold
```

随后在 Pi 中输入 `/reload`，或重启 Pi。

也可以手动克隆到全局扩展目录：

```bash
git clone https://github.com/lizhuoran1019/pi-auto-fold.git ~/.pi/agent/extensions/auto-fold
```

两种方式选一种即可；已经手动安装的用户不必再次运行 `pi install`，避免加载两份插件。宿主提供运行时依赖，无需另行执行 `npm install`。手动安装后同样需要 `/reload`。

通过包管理器安装后，可用以下命令更新或卸载，再执行 `/reload`：

```bash
pi update git:github.com/lizhuoran1019/pi-auto-fold
pi remove git:github.com/lizhuoran1019/pi-auto-fold
```

## 操作

| 操作 | 效果 |
| --- | --- |
| 点击摘要行 | 展开/折叠这一组（终端需支持鼠标） |
| `Alt+O` 或 `/fold` | 展开/折叠最近一组 |
| `/fold expand` | 展开所有已分组过程 |
| `/fold collapse` | 折叠所有已分组过程 |
| `/fold off` | 暂停自动折叠，恢复原始显示 |
| `/fold on` | 重新开启 |
| `/fold status` | 查看分组数量、对话区域识别情况及是否正在执行 |

展开分组后，原生 `Ctrl+O` 仍然控制每个工具的详细输出；本插件不改这个快捷键。若 `Alt+O` 被终端或别的插件占用，直接用 `/fold`。

开关和各组展开状态只保存在当前运行中，不写入设置。重载、切换会话或重启后默认重新开启；恢复会话、切换分支、压缩后的历史会重新识别。

## 安全边界

- **只改变显示**：不修改消息、会话记录、模型上下文或工具执行，也不替换编辑器、页脚和其他工具渲染器。
- 等待 `agent_settled`，不在 `agent_end` 时抢先折叠；自动重试和后续执行期间保持新输出可见。
- 没有成功最终回答的失败、中断、长度截断，以及缺少结果的工具调用，不会自动隐藏。
- 成功回答前已恢复的失败记录可以折叠，但摘要保留失败数量，可随时展开查看。
- 真实用户消息、自定义消息、分支/压缩摘要作为分界；未知组件和其他插件通知保留原样。
- ACP 子任务完成/失败通知虽然被宿主存成用户消息，但属于同一轮执行过程。匹配完整通知格式后一起分组，失败通知计入摘要警告；只引用通知标题的真实提问不会被隐藏。
- 回答之前的已完成原生 shell 命令可以折叠。**回答之后新增或延后显示的 shell 命令保留原样**，不猜测它们属于哪一轮，以免误藏独立命令。
- RPC、JSON、print 模式不操作界面。导出 HTML 不受影响。

## 兼容性

已针对 **Pi 1.5.2 / Node 24** 验证。Pi 暂无公开的整段对话折叠接口，因此本插件使用公开组件类，读取经过检查的内部完成状态，并仅包装现有组件实例的 `render` / `handleMouse`。不修改全局原型，也不修改 Pi 安装文件。

遇到不认识的组件/状态时保持原样；安装包装器失败时恢复显示并停用。Pi 升级可能导致折叠不生效，需要重新适配。可以随时用 `/fold off` 恢复原始显示；删除或移走本目录后 `/reload` 可卸载。

## 测试

在仓库根目录执行（需要已安装 Pi）：

```bash
npm test
npm run test:tui
```

19 项组件/生命周期测试使用本机 Pi 加载器和组件。默认从 `npm root -g` 查找 Pi；非 npm 全局安装时可设置 `PI_PACKAGE_ROOT` 为 Pi 包目录。覆盖最终回答保留、失败/中断保护、通知与真实提问的分组、鼠标坐标、窄屏、展开状态、第三方包装器共存、只读方法回滚、真实工具与 shell 组件、独立图片输出、异步分支重建、压缩结束、重载清理及非 TUI 模式。

另有真实 CLI 的 fullscreen PTY 冒烟测试（Linux/macOS，Python 3）：使用临时配置和虚构会话，离线启动已安装的 `pi`，验证跨子任务通知的折叠，以及展开、折叠、停用/启用、`/reload`。不会调用模型或修改现有会话；可设置 `PI_BIN` 指定 Pi 可执行文件。

另已使用宿主包类型声明做 `strict` TypeScript 检查。独立扩展不自带运行时依赖；编辑器若提示找不到宿主包，是普通 Node 模块解析与 Pi 加载器别名的差异。
